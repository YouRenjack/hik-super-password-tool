# 海康门禁一体机「超级密码」批量修改工具

针对 **DS-K1T6-HS**（DS-K1T6 系列人脸识别门禁一体机）及采用同代门禁固件的
DS-K1T3xx / DS-K1T67x / DS-K1T8xx / 门禁主机，按 Excel 清单**批量**读取和修改**超级密码**。

只要设备网页端有「配置 → 门禁配置 → 门参数 → 超级密码」这一项，就适用。

---

## 一、先确认改的是哪个密码

| 名称 | 作用 | 本项目 |
| --- | --- | --- |
| **超级密码** `superPassword` | 门参数里 4~8 位数字，在键盘/触摸屏上**输入即开门**（万能开门口令） | ✅ 操作对象 |
| 管理员密码 / 激活密码 | 登录设备网页、SADP、iVMS-4200 的账号密码 | ❌ 仅用于登录 |
| 胁迫码 `stressPassword` | 被胁迫时开门并上报胁迫事件 | ❌ 不动 |

> 手册原文：「超级密码：指定人员输入超级密码即可开门。胁迫码和超级密码不能重复，一般为 4-8 位的数字。」

脚本用**管理员密码登录**设备，只替换门参数里的 `superPassword` 一个字段，其余配置原样回写。

## 三、快速开始（三步）

### 第 1 步：填表

打开 [`devices_template.xlsx`](devices_template.xlsx)，把「设备清单」页的示例行换成真实设备：

| 设备IP | 门号 | 新密码 | 备注 |
| --- | --- | --- | --- |
| 192.168.1.64 | 1 | 135790 | 北门 |
| 192.168.1.65 | 1 |  | 南门 |
| 192.168.1.70 | 2 | 246810 | 门禁主机-2号门 |

规则：

- **只有 IP 是必填**。门号留空 = 1；新密码留空 = 用命令行 `-n` 指定的统一密码。
- IP 支持 `192.168.1.64`、`192.168.1.64:8000`、`https://192.168.1.64` 三种写法。
- 表头必须是「设备IP」（也认 `IP` / `IP地址` / `设备地址` / `host`），放在前 10 行内都能自动找到。
- 同一 IP 可重复出现，但门号必须不同，否则只处理第一条。

### 第 2 步：预演（强烈建议）

```powershell
#只校验结果不会真实写入，主要目的为验证
python batch_update.py -i devices_template.xlsx -n 135790 --password abcd2025 --dry-run
```

`--dry-run` 只读取门参数、生成报文，**不写入设备**。这一步能一次性确认：IP 是否可达、账号密码是否正确、设备是否都有超级密码字段。

### 第 3 步：正式执行

```powershell
#方式1（需在csv文件里填写密码列）
python batch_update.py -i devices_template.xlsx --password abcd2025
#方式2（无需在csv文件填入更多信息，仅需通过-n参数传入密码即可）
python batch_update.py -i devices_template.xlsx -n 135790 --password abcd2025
```

执行完看 `output/report_*.csv`，每台设备一行，失败原因写在「说明」列。

## 四、运行环境与权限要求

### 4.1 运行环境

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11、Windows Server 2016+；Linux、macOS 同样可跑 | 纯标准库实现，不绑定平台。本文示例用 PowerShell，Linux 下换成 `python3` 即可 |

| 外网 / 互联网 | **不需要** | 全程只与内网设备通信，不联海康云 |

| 控制台编码 | UTF-8 最佳（非必须） | 脚本已强制按 UTF-8 输出；GBK 控制台可能出现方块字，但不影响执行结果 |

```powershell

python -c "import openpyxl; print('openpyxl', openpyxl.__version__)"   # 只用 CSV 时可跳过
```

### 4.2 权限要求（设备 / 本机 / 网络 / 合规）

#### ① 设备侧权限 —— 必须有，缺一不可

| 需要什么 | 具体要求 | 不满足的表现 |
| --- | --- | --- |
| 有效设备账号 | 默认 `admin` + 激活密码；也可用其它管理员账号 | `认证失败 (HTTP 401)` |
| 账号具备**远程配置**权限 | 管理员账号默认具备；只读/操作员账号可能被拒 | `HTTP 403` 或「写入被拒绝」 |
| 设备已激活 | 未激活的设备不接受登录 | 401 或登录页强制激活 |
| 账号未被锁定 | 连续输错会锁 30 分钟（重启设备可立即解锁） | 401，且密码正确也进不去 |
| ISAPI / HTTP 已开启 | 网页端能正常登录即可，默认端口 80；改过端口用 `--port` | 连接超时或 404 |
| 固件支持门参数接口 | 设备网页端有「门禁配置 → 门参数」即可 | `读取门参数失败` + 一串 404 |
| 门号真实存在 | 多门设备才需要；单门一体机固定 1 | 「找不到门号 N」 |

> 脚本**不绕过鉴权**：拿不到管理员密码就无法修改，这是设计前提。密码忘了只能走官方重置流程（见第十一节）。

#### ② 电脑本机权限 —— 权限要求很低

**普通用户即可，不需要管理员 / root，不需要管理员权限的 PowerShell。**

| 需要 | 不需要 |
| --- | --- |
| 读取清单表格（只读） | 安装系统服务、驱动、注册表写入 |
| 在程序目录写 `output/` 报告与日志 | 关闭防火墙、开放入站端口 |
| 发起出站 TCP 连接 | 管理员身份运行 CMD/PowerShell |
| — | 任何系统级配置修改 |

唯一例外：把程序放到 `C:\Program Files` 这类受保护目录才需要提权。**建议直接放在用户目录或 D 盘普通目录**，就完全不用管理员。如果 `output/` 目录不可写，用 `--report` 指到有写权限的路径。

#### ③ 网络权限

- **出站** TCP 到设备：默认 `80`；HTTPS 为 `443`；改过端口则用 `--port` 或表格里写 `IP:端口`。
- **入站**：完全不需要（本工具是客户端，不监听端口）。
- 跨网段时，中间防火墙/ACL 需放行「本机 → 设备」的上述端口；走 VPN 也可以。
- 设备若配置了**管理 IP 白名单**，要把运行本脚本的电脑 IP 加进去。
- 不需要访问互联网，不需要海康云眸/ISUP 平台。

#### ④ 组织与合规权限

- 需要设备**所有者或管理方的书面授权**；批量修改开门口令属于生产变更，建议走变更审批并留存报告。
- 报告里的新密码是明文凭据，按密码管理要求保管（见第十节）。

### 4.3 最小权限速查

| 角色 | 需要给什么 |
| --- | --- |
| 设备账号 | 一个管理员账号（远程配置权限），仅此而已 |
| 本机账号 | 普通用户 + 对程序目录的读写 |

### 4.4 环境类报错对照

| 报错 | 缺的是什么 | 怎么解决 |
| --- | --- | --- |
| `'python' 不是内部或外部命令` | 没装 Python 或没进 PATH | 去 python.org 装 3.8+，安装时勾选 “Add Python to PATH” |

| `-v, --verbose` | 调试日志 | 关 |

### 新密码以谁为准（优先级）

| 优先级 | 来源 | 何时生效 |
| --- | --- | --- |
| 1（最高） | 表格「新密码」列 | 该行填了值 → 用它，`-n` 被忽略 |
| 2 | 命令行 `-n` | 该行留空 → 用 `-n` |
| 3 | `--random` | 前两者都没有 → 每台随机生成 |
| — | 都没有 | 该行判为「参数错误」，不会静默跳过 |

- 表格列和 `-n` **同时存在且不一致**时，按表格执行，并在日志里打印告警：
  `第 N 行：表格填的新密码 123457 与命令行 -n 135790 不一致，按表格执行。`
- 两种典型用法：
  - **全表统一密码** → 「新密码」列**清空**，运行时给 `-n 135790`；
  - **逐台不同密码** → 每行都填好该列，运行时**不用** `-n`。

### 两个“密码”别混

| 密码 | 干什么用 | 从哪来 |
| --- | --- | --- |
| **设备登录密码**（管理员密码） | 登录设备、通过 401 认证，**每次运行都必须有** | `--password` → 环境变量 `HIK_PASSWORD` → 交互输入 |
| **新超级密码**（要设置的值） | 写进门参数，供开门用 | 表格列 → `-n` → `--random` |

所以：**表格里填好了新密码，运行时就不需要再给 `-n`**；但设备登录密码（如 `abcd2025`）仍然要给，否则脚本会提示你输入。

### 密码怎么传更安全

```powershell
$env:HIK_PASSWORD = "abcd2025"
python batch_update.py -i devices_template.xlsx -n 135790
```

命令行 `--password` 会留在 PowerShell 历史里，长期使用建议走环境变量。

## 七、批量执行策略

这些设计都是为了**别把现场搞挂**：

1. **并发可控**：默认 8 线程，每台设备一个独立 ISAPI 会话；`--workers 1` 可退化为串行。
2. **认证失败不重试且默认中止整批**。密码错时继续跑会把清单里每台设备的账号都锁一遍（海康连续输错会锁 30 分钟），所以第一台 401 就停，改完密码再加 `--allow-auth-continue`。
3. **只重试网络错误**：超时、连接被拒，指数退避（1s、2s…最多 5s）。
4. **断点续跑**：`--resume output/report_xxx.csv` 跳过已成功且目标密码相同的设备，失败修复后只补跑失败项。
5. **去重**：同一 IP+端口+门号只处理一次。
6. **改前验明正身**：先读 `deviceInfo`，型号不是 `DS-` 开头就跳过（IP 被回收/改分配时能拦住）。
7. **改后回读校验**：PUT 之后再 GET 比对，避免「提示成功其实没生效」。

## 八、工作原理

```
GET  /ISAPI/AccessControl/Door/param/1      # 读整份门参数
     ↓ 只替换 <superPassword>…</superPassword>（明文 ↔ Base64 自动转换）
PUT  /ISAPI/AccessControl/Door/param/1      # 原样回写
     ↓
GET  回读比对
```

兼容性处理：

- **两种报文结构**：旧固件 `<Door>`（hikvision.com/ver20）+ 新固件 `<DoorParam>`（isapi.org/ver20），
  以及多门的 `<DoorParamList>` 列表，都能正确定位；
- **两种密码编码**：部分固件（如 DS-K1T6-HS V4.38）把 `superPassword` 以 **Base64** 存储
  （`ODgwNzI1` = `880725`），脚本读时自动解码、写时按原编码回写；
  只接受明文的固件则原样透传，不会画蛇添足；
- 路径 `/Door/param/{门号}` 与 `/DoorParam/{门号}` 自动尝试；
- XML 读不到时自动改用 `?format=json`（新固件门禁一体机默认走 JSON）；
- 门参数缺 `superPassword` 节点时插入到 `<doorNo>` 之后；
- 多门设备按 `<doorNo>` 精确定位，不会误改别的门；
- 认证为 HTTP Digest，不绕过任何鉴权。

> 编码探测规则：字段长度是 4 的倍数、字符集符合 Base64、且解码结果是可打印短字符串**同时满足**才判定为编码值；
> 像 `880725` 这种 6 位明文不会被误判。

## 九、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 全部 `认证失败` | 密码错、账号被锁（等 30 分钟或重启设备）、或设备未激活。先用网页登录验证一次 |
| 全部 `无法连接 … timed out` | IP 不通 / 端口不对 / 跨网段被防火墙拦。`Test-NetConnection 192.168.1.64 -Port 80` |
| `读取门参数失败` + 一串 404 | 固件不支持该 ISAPI 路径，或该型号没有键盘/超级密码功能。加 `-v` 看具体返回 |
| `写入被拒绝 statusCode=4` | 设备不允许经 ISAPI 改该字段，只能走网页端或设备本地（见第十一节） |
| `写入失败：HTTP 400 … badXmlContent` | 密码字段编码不匹配：这台设备要求 Base64 而写的是明文（或反之）。1.2.0 起自动识别；老版本先 `--dump` 看 `<superPassword>` 里是明文还是 `ODgwNzI1` 这种串 |
| 报告里「新密码」和命令行的 `-n` 不一致 | 表格「新密码」列优先级更高，会覆盖 `-n`；执行时日志会打印告警。想用 `-n` 就把该列清空 |
| `非海康设备（…），未修改` | 该 IP 上是别的设备；确认清单或加 `--no-require-hikvision` |
| 部分行 `参数错误` | 该行 IP 格式不合法 / 门号不是整数 / 新密码不是 4~8 位数字，按「说明」列改表格 |
| 报告里 `原密码` 是 `****` | 正常，原密码固定打码 |
| 想重跑但不想动已成功的 | 加 `--resume output/上次报告.csv` |

## 十、安全与合规

- **仅用于你拥有或已获授权管理**的设备。批量改开门口令属于高风险操作，执行前请确认范围。
- 执行前先 `--dry-run`，并抽 1 台在网页端核对原超级密码，确认清单没填错。
- 报告里的「新密码」是明文，且是**唯一**的记录来源（尤其 `--random` 模式）。请离线保存、限制访问，不要放到共享盘或代码仓库。

## 十一、附：其它改法与兜底

**管理员密码怎么改**：网页端「配置 → 安全管理 → 修改管理员密码」；或 iVMS-4200 设备管理 → 修改设备密码。

**超级密码 ISAPI 走不通时**：

1. 网页端：配置 → 门禁配置 → 门参数 → 超级密码；
2. 设备本地：触摸屏 → 设置（管理员验证）→ 门禁设置 → 门参数；
3. iVMS-4200：远程配置 → 门禁参数 → 门参数。

**管理员密码彻底忘了**：SADP「忘记密码」→ 导出 XML / 出示安全码 → 海康售后凭购买凭证换临时密码；或复位键恢复出厂（会清空人员、人脸、卡片与全部配置）。没有正当脚本能绕过这一步。
